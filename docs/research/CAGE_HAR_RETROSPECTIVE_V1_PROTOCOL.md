# CAGE-HAR v1 fully nested retrospective source protocol

Status: locked on 2026-09-04 before the fully nested five-seed run.

## Why this lane exists

The prospective CAGE-HAR implementation originally rejected all consumed InclusiveHAR evidence.
That was correct for an independent validation claim but unnecessarily prevented a useful
retrospective development evaluation. InclusiveHAR source participants 1--10 contain the native
six primary channels and three gravity channels required by CAGE-HAR. This lane uses those data to
measure whether the already frozen implementation helps on the same source-development problem as
RMRP and CTGR.

The result is real human-data evidence, but it is not independent validation. CAGE-HAR was invented
after inspecting aggregate and participant-level CTGR behavior on these same participants. The
analysis must always be described as retrospective reused-source development.

## Method freeze and preliminary probe

The CAGE-HAR code and parameters were frozen at tag `cage-har-implementation-v1`, commit
`3d1e8ae444b9976c7d532b39142ae58d4fe41aad`, before this protocol. No CAGE parameter may change in
response to this run.

Before this fully nested protocol was written, a non-persisted feasibility probe applied the router
to the five preserved global OOF arrays. It produced approximately 0.8293 for CAGE-HAR and 0.8612
for the global trust blend. That probe is not publication evidence because predictions used to
train the second-level router were not regenerated inside the held router participant partition.
It is disclosed here, and it caused no method or hyperparameter change.

## Fully nested evaluation

The original five source outer folds and four inner folds per outer partition are reused. For each
of the five fixed seeds:

1. The selected CTGR expert family for an outer fold is read from the previously frozen CTGR
   candidate map.
2. RMRP base and gravity-posture expert predictions for the eight outer-training participants are
   regenerated by the four participant-exclusive inner folds.
3. CAGE decision repair, harm/tail weights, counterfactual targets, ridge router and participant
   jackknife are fitted only from those inner-OOF predictions and outer-training labels.
4. Label-free gauge and health features use per-window quantities plus channel scales fitted from
   the outer-training partition only.
5. Evaluation uses the preserved RMRP, gravity-expert and CTGR probabilities for the two outer-test
   participants. Their labels are unavailable to repair, routing and model fitting and are used
   only after probabilities are fixed.
6. The five outer partitions cover source participants 1--10 exactly once. Participant-level
   metrics are aggregated for each seed, followed by descriptive five-seed summaries.

The fixed method set is uncalibrated RMRP, decision-repaired RMRP, global trust-region blend,
confidence-gated trust-region blend, disagreement-gated trust-region blend, full CAGE-HAR, and the
frozen CTGR reference. CAGE retains the parameters in `cage_har_v1.yaml`; no retrospective grid is
introduced.

Inner base seeds are `seed + inner_index`. Inner expert seeds are
`seed + 101*view_index + 17*estimator_index + inner_index`, matching the existing deterministic
CTGR inner-model convention while applying it to every fixed evaluation seed.

## Evidence boundary

- Participants 1--10 are reused source-development evidence.
- Participants 11--20 must not be loaded or reopened.
- DAGHAR data and predictions must not be loaded.
- No outcome from this run is confirmatory or supports a generic state-of-the-art claim.
- The prospective new-cohort protocol remains unchanged and is still required for advancement.
- The raw CSV has no explicit fault mask, so clean released rows are treated as observed. Synthetic
  fault behavior remains contract testing and cannot become a real robustness claim.

The exact paths, hashes, seeds, nesting rules and preliminary-probe disclosure are frozen in
`configs/experiments/cage_har_retrospective_v1.yaml`.
